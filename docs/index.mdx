## Start in a minute

<PackageManagerTabs
  command={{
    npm: 'npm install react-websocket',
    pnpm: 'pnpm add react-websocket',
    yarn: 'yarn add react-websocket',
    bun: 'bun add react-websocket'
  }}
/>

```tsx
import { useWebSocket } from 'react-websocket';

export function Echo() {
  const { status, lastMessage, send } = useWebSocket('wss://echo.websocket.org');

  return (
    <div>
      <p>Status: {status}</p>
      <p>Last message: {String(lastMessage ?? '—')}</p>
      <button onClick={() => send('hello')}>Send</button>
    </div>
  );
}
```

No provider, no setup and no `useEffect`. That component already:

- Shares one socket with every component that uses the same URL, through StrictMode, `<Activity>` and route changes.
- Reconnects with exponential backoff and jitter, and at once when the network or the tab comes back.
- Queues messages sent before the socket opens, and delivers them in order once it does.
- Never connects during a server render, and hydrates without mismatches.

### Add types when you're ready

Most servers send JSON. Turn on `json` and name what you receive and what you send:

```tsx
import { useWebSocket } from 'react-websocket';

type Price = { symbol: string; price: number };

function Ticker() {
  const { status, lastMessage, send } = useWebSocket<Price, { subscribe: string }>(
    'wss://api.example.com/prices',
    {
      json: true,
      // Runs after every (re)connect, by which time `send` is assigned.
      onOpen: () => send({ subscribe: 'ACME' })
    }
  );

  if (status !== 'open') return <p>{status}…</p>;
  return <p>ACME: {lastMessage?.price ?? '—'}</p>;
}
```

To check messages at runtime too, pass a `schema` from zod, valibot or arktype, and the types are inferred from it. The [getting started guide](./guide/getting-started.mdx) goes on from here.

## The toolkit

Everything builds on the client that `useWebSocket` uses. Each piece is a separate import, so a page that only connects ships only the core, about 4 kB, and most pieces add under 2 kB. None of them imposes a wire protocol: you describe your server's messages, and they do the bookkeeping.

## Works with your stack

react-websocket uses the standard `WebSocket` API, so any WebSocket server works: Node's `ws`, Hono, Django Channels, Tornado, Go, Phoenix or Cloudflare Durable Objects. In the browser it runs in a Vite app or in a server-rendered framework such as [Next.js, React Router or Astro](./guide/ssr.md), and [`react-websocket/core`](./guide/without-react.md) brings the same client to code without React.

The repository has runnable [examples](https://github.com/mehmetkose/react-websocket/tree/main/examples) for Next.js, Astro, Remix, Hono and Tornado, and a multiplayer game. The [real-world guides](./recipes.md#real-world-guides) build whole apps, client and server: an [AI chatbot](./recipes/ai-chatbot.md), a [voice assistant](./recipes/voice-assistant.md), a [party game](./recipes/party-game.md), a [team chat](./recipes/team-chat.md), a [trading dashboard](./recipes/trading-dashboard.md) and more.
